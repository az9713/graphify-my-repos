# claude-token-dashboard
# Claude Code Token Dashboard

A local web dashboard that shows exactly where your Claude Code tokens are going — sessions, turns, input/output tokens, cache reads, cache creates — broken down by model, project, and tool.

![Claude Code Token Dashboard](docs/token_dashboard.jpg)

---

## Inspiration

This dashboard was inspired by the YouTube video **"How to Never Hit Your Claude Session Limit Again"** by Nate Herk:
[https://www.youtube.com/watch?v=_qZvORxGqI0](https://www.youtube.com/watch?v=_qZvORxGqI0)

The video explains how tokens compound as sessions grow, why context rot degrades performance, and why knowing where your tokens actually go is the first step to managing them. This dashboard makes that visibility concrete and personal.

---

## What It Shows

| Tab | What you see |
|-----|-------------|
| **Overview** | 7 headline stat cards (sessions, turns, input, output, cache read, cache create, estimated cost) + 24-hour activity heatmap |
| **Daily** | Line chart of sessions and messages per day (7d / 30d / all time) |
| **Models** | Token breakdown and estimated cost per model (Opus, Sonnet, Haiku) |
| **Projects** | Sessions and token totals grouped by project directory |
| **Sessions** | Paginated table of every session — date, duration, tokens, first prompt, flags |
| **Tools** | Aggregate call counts for every tool Claude used (Read, Bash, Edit, Write, etc.) |
| **Tips** | Your most-used slash commands and most active projects from command history |

## Quick Start

**Requirements:** Python 3.8+, Claude Code installed (data files must exist at `~/.claude/`)

```bash
git clone https://github.com/az9713/claude-token-dashboard.git
cd claude-token-dashboard
pip install -r requirements.txt
python app.py
```

The browser opens automatically at `http://127.0.0.1:5000`.

## How It Works

The dashboard reads three files that Claude Code writes automatically — no agents, no API calls, no configuration needed.

| File | What it contains | Which tabs use it |
|------|-----------------|-------------------|
| `~/.claude/stats-cache.json` | Pre-computed aggregate token totals by model and day | Overview, Daily, Models |
| `~/.claude/usage-data/session-meta/*.json` | One file per session — tokens, tools, duration, first prompt | Projects, Sessions, Tools |
| `~/.claude/history.jsonl` | Every command you have typed, with timestamps | Tips |

The session-meta files are read live on every request — new sessions appear immediately without restarting the server. The stats-cache is a periodic snapshot computed by Claude Code; when it is stale the dashboard shows a yellow banner.

> **Understanding the numbers in depth:** See [`docs/TOKEN_DASHBOARD_STATS.md`](docs/TOKEN_DASHBOARD_STATS.md) for a complete reference that explains the exact source field and calculation behind every single statistic shown in the dashboard — including why cache-read tokens typically dwarf raw input tokens by 100–1000×, how the estimated cost is computed, which tabs are live vs. stale, and what the dashboard cannot show.

---

## The Staleness Banner

The stats-cache is regenerated by Claude Code on its own schedule — not by this dashboard. If it is more than 7 days old, a yellow banner appears:

> ⚠ Stats cache last updated YYYY-MM-DD. Overview · Daily · Models reflect data through that date. Projects · Sessions · Tools tabs are always live.

When this banner is visible, switch the date range to **"All time"** to see historical data on the Daily chart. The Projects, Sessions, and Tools tabs are unaffected — they always read the live session files.

## Pricing Used for Cost Estimates

Costs are estimated using Anthropic published list prices. Actual charges depend on your subscription, credits, and any enterprise pricing.

| Model tier | Input | Output | Cache Read | Cache Create |
|------------|-------|--------|------------|--------------|
| Opus | $15.00/M | $75.00/M | $1.50/M | $18.75/M |
| Sonnet | $3.00/M | $15.00/M | $0.30/M | $3.75/M |
| Haiku | $0.25/M | $1.25/M | $0.025/M | $0.3125/M |

The key insight: for active Claude Code users, **cache-read tokens typically account for the majority of estimated cost**, not output tokens. The Models tab makes this visible per model.
