---

## What is a Cheat Code?

A **cheat code** is a compressed, operational knowledge artifact that lets you perform reliably under pressure. It's not notes—it's a decision-and-action sheet that transforms messy domain knowledge into executable rules.

A cheat code is "good" if and only if:
- It produces your target verb (Solve/Build/Decide/Explain/Predict) reliably
- It includes failure modes for every heuristic
- It passes the 3-layer verification stack
- Someone with basic domain literacy can use it immediately

## Quick Start

### Using a Cheat Code

1. **Find the relevant cheat code** in the category that matches your need
2. **Read the Goal** to confirm it matches your situation
3. **Check Diagnostics** to assess your current state
4. **Follow the Playbook** step by step
5. **Watch for Failure Modes** mentioned in each step
6. **Verify** using the Verification Checklist

## Cheat Code Template

Every cheat code follows this structure:

```markdown
# CHEAT CODE: [Topic]

**Domain:** [Category] | **Verb:** [Solve/Build/Decide/Explain/Predict]
**Complexity:** [Low/Medium/High] | **Update Cadence:** [Static/Annual/Quarterly]

## Goal
[What this enables you to do]

## Invariants
[Timeless principles with falsifiability markers]

## Primitives
[Objects, Operators, Metrics]

## Canonical Tasks
[The 80/20 problems this domain keeps repeating]

## Models + Failure Modes
[Approaches with when/how they fail]

## Key Equations / Heuristics
[Rules with failure modes]

## Traps & Misconceptions
[Common mistakes and why they're wrong]

## Diagnostics
[Self-assessment checklist]

## Playbook
[Step-by-step actions with failure modes]

## Verification Checklist
[Identity, Scale, Empirical checks]

## Toy Problem
[Simplified practice scenario]

## Real Case
[Actual application with complexity]

## Next Upgrades
[What to learn next]

## Cross-Domain Links
[Related cheat codes]
```
