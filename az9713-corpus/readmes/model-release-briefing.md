# model-release-briefing

A Claude Code skill that reads your conversation history, understands how you actually use Claude, and matches those workflows against new model features to produce a personalized briefing and hands-on tutorial you can follow immediately.

## The Problem

Every Anthropic model release means the same grind: read the blog post, skim the changelog, figure out which features matter for your work, try them, hit undocumented gotchas, backtrack. The information is scattered across blog posts, docs, and community analysis -- and none of it is personalized to what you do.

## What This Skill Does

You point it at your source materials (blog posts, transcripts, changelogs saved locally) and invoke one command. It runs a six-phase pipeline:

1. **Ingests source materials** -- reads everything in the folder you provide
2. **Learns your workflows** -- pulls context from your Claude Code history, memory files, and conversation patterns (or asks four quick questions if it doesn't know you yet)
3. **Generates a personalized briefing** -- walks through every change in the release, ranked and explained in terms of your specific role and daily work
4. **Selects tutorial features** -- picks the 3-5 features with the highest impact on your actual workflows, confirms with you
5. **Builds a self-contained tutorial** -- complete prerequisites, working code, progressive exercises, troubleshooting tables -- zero external docs needed
6. **Verifies against official docs** -- fetches API references and SDK changelogs to catch errors before you hit them (this phase is non-negotiable -- it caught deprecated parameters, missing feature flags, and model-exclusive behaviors during development)

## Quick Start

```bash
# 1. Copy the .claude/skills/model-release-briefing/ folder into your project

# 2. Gather source materials into a docs/ folder
#    (blog posts, transcripts, changelogs as .txt files)

# 3. Launch Claude Code from the project directory
claude

# 4. Invoke the skill
/model-release-briefing claude-5 ./docs
```

The skill will walk you through the rest interactively.

## What You Get

Two deliverables tailored to your workflows:

**Personalized Briefing** -- every change in the release explained through the lens of what you do. Opens with "What Matters Most for You" (top 3-4 features), closes with "Practical Takeaways" (3-7 things to try today).

**Hands-On Tutorial** -- self-contained, copy-pasteable exercises for the features that matter most to you. Includes global prerequisites (Node.js, SDK versions, subscriptions), per-feature prerequisites (env vars, feature flags, opt-in steps), and troubleshooting for every exercise.

## Why Verification Matters

During development, Phase 6 caught errors that would have made the tutorial non-functional:

| Error | Source | Impact |
|-------|--------|--------|
| Agent teams required `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` | Not mentioned in any blog post or transcript | Entire section would silently fail |
| `budget_tokens` parameter deprecated | Blog post used pre-release API | SDK would reject the parameter |
| `"max"` thinking budget was Opus-exclusive | Blog implied universal | Would fail on Sonnet/Haiku |

Blog posts and community summaries are unreliable for technical details. The skill verifies every claim against official API docs before presenting the tutorial.
